## 3. Main bug

The user has approximately **3,907 photos associated with 12 February 2024** in Samsung Gallery. This date is associated with transferring/backing up photos from their old phone to their new phone.

When the user selects 12 February 2024, DocuSweep reports that no photos match the date filter.

When selecting 12–13 February 2024, the diagnostic popup appears and reports that Android returned approximately 24,223 photos, with the reported date range extending from 1 January 1970 to 23 October 2026.

A subsequent timestamp diagnostic showed:
- Zero photos matching the selected range using `asset.creationTime`.
- No records among the sample that formatted to 12 February 2024.

This suggests that the date displayed by Samsung Gallery may differ from the `creationTime` value returned by the Expo MediaLibrary API. The exact cause is not yet proven.

**Likely area to investigate:** Original photo capture dates stored in EXIF metadata versus Android MediaStore timestamps and Expo MediaLibrary asset fields. Transferred photos may preserve their original capture dates while their media-library timestamps reflect a different date.

Do not assume that every photo has EXIF metadata, or that every date displayed in Samsung Gallery necessarily comes from the same metadata field.

## 4. Current scan implementation

The scan function in `app/index.tsx` requests photo access and retrieves gallery photos using pagination:

```tsx
const page = await MediaLibrary.getAssetsAsync({
  mediaType: 'photo',
  first: 100,
  after: cursor,
  sortBy: [[MediaLibrary.SortBy.creationTime, false]],
});
```

It accumulates the pages into `assets`, then computes date boundaries:

```tsx
const from = getDayStart(startDate).getTime();
const to = getDayEnd(endDate).getTime();
```

The current filter is:

```tsx
const selectedDateAssets = assets.filter(
  (asset) => asset.creationTime >= from && asset.creationTime <= to
);

assets = selectedDateAssets;
```

This compares `asset.creationTime` directly with the selected date range. This is the main logic that needs investigation and correction.

The code also contains diagnostic code that shows the selected date range, total retrieved photos, and earliest/latest creation dates.

A temporary metadata diagnostic was added to inspect sample assets:

```tsx
const info = await MediaLibrary.getAssetInfoAsync(asset);
```

It attempts to read:
- `info.modificationTime`
- `info.exif.DateTimeOriginal`
- `info.exif.DateTimeDigitized`
- `info.exif.DateTime`

That diagnostic caused an Android error indicating that `ACCESS_MEDIA_LOCATION` permission was missing.

The user was instructed to remove the temporary `sampleDates` / `samplesWithDates` / `Photo metadata check` diagnostic block, while retaining:

```tsx
assets = selectedDateAssets;
```

The user has not yet confirmed whether that removal has been completed. **Inspect the actual current source before making further edits.**

## 6. Existing OCR functionality to preserve

The app dynamically imports the native ML Kit recognizer when scanning begins:

```tsx
const textRecognition = await import(
  '@react-native-ml-kit/text-recognition'
);

recognizeText = (uri) => textRecognition.default.recognize(uri);
```

It extracts recognized text and evaluates word and line counts. The current first-pass match criteria are:

```tsx
if (
  wordCount >= 8 ||
  lineCount >= 3 ||
  (wordCount >= 4 && asset.width > asset.height * 0.8)
) {
  // Add to document matches
}
```

Preserve this OCR behavior unless a separate issue is discovered. The current evidence points to the date-selection stage, not the OCR thresholds.

Photo deletion must remain a user-reviewed action. Never delete photos automatically during scanning or debugging.
