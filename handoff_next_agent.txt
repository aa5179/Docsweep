   - MediaLibrary photo permissions and limited-access handling
   - Paginated gallery retrieval
   - Inclusive start/end date filtering
   - EXIF-aware fallback date resolution with safe metadata failures
   - OCR using @react-native-ml-kit/text-recognition
   - Face filtering using @react-native-ml-kit/face-detection
   - Existing OCR thresholds are preserved:
       wordCount >= 8
       lineCount >= 3
       wordCount >= 4 && asset.width > asset.height * 0.8

   - Result selection/deselection

Known design tradeoffs
----------------------
- The reference uses Space Mono and Nunito Sans. The project already loads Inter;
  the shell uses Android monospace for HUD labels and Inter/default body text instead
  of adding another font dependency.
- The reference uses pixel-art detective imagery. The shell uses lightweight Ionicons
  mascot treatments because no verified local pixel-art asset was available.
- The design folder contains decorative/fake sample stats. Those were intentionally
  not copied into production because the app has no real values for them yet.
- The deletion modal is custom and retro-styled, but the actual Android deletion
  approval flow and success/failure alerts remain unchanged.

Safety notes
------------
- Never delete photos automatically.
- Do not remove limited photo access handling.
- Do not change OCR thresholds without a separate request.
- Do not reintroduce the old EXIF diagnostic alert. getAssetInfoAsync can fail when
  media-location permission is unavailable; the date resolver must remain best-effort.
- Inspect git status before editing. Existing unrelated files may be dirty.
